# Contributing

🇧🇷 [Em português](#em-português)

Thanks for helping! Lighthouse for ether.fi Cash is a client-side dashboard: no server, no database, no telemetry. You **do not need an ether.fi account** to work on it: the demo and the synthetic fixtures cover every screen and rule.

## The one rule: never commit real data

Financial data is personal and a push is forever. Never put real transactions, merchant names from a real statement, amounts, balances, wallet or deposit addresses, transaction or card ids, card digits, emails, tokens or account screenshots in code, comments, tests, fixtures, docs, issues, pull requests or commit messages, including your own data.

- Examples are always made up (`FARMACIA EXEMPLO 0001`, `0xSAMPLE-…`, `.example` domains).
- Real data lives only in the data folder, outside git. One resolver (`scripts/data-dir.mjs`) picks it for the pull, the dev server, the checks and the privacy scan, in this order: `LIGHTHOUSE_DATA_DIR`; `lighthouse-data` in your user folder (`%USERPROFILE%\lighthouse-data`, `~/lighthouse-data`), if it exists; `fixtures/live/` (git-ignored). Prefer the user folder: it is out of the project and **out of cloud-synced folders** (OneDrive, iCloud Drive, Dropbox, Google Drive), and the files are your full financial history. `node scripts/data-dir.mjs` shows which one is in use. The pull refuses a folder inside the project other than `fixtures/live/`, because git would commit it.
- Screenshots in issues and PRs come **only from the demo or the synthetic fixtures**.
- If you have real data on your machine, run `npm run privacy` before every commit (see below).

## Setup

You need **Node ≥ 22.23.4** (`.nvmrc` says 22.23.4; the checks use `--experimental-strip-types`, which older Node versions don't have) and npm.

```bash
npm ci
npm run dev        # http://localhost:5173 (demo)
```

| Address | Data |
|---|---|
| `http://localhost:5173/` | demo: fictional, deterministic, with dates that follow today |
| `http://localhost:5173/?fixtures=sample` | synthetic connector responses from `fixtures/sample/` (raw format, through the real normalization) |
| `http://localhost:5173/?fixtures` | your own data from `npm run pull`, if you have an account (dev only) |

## Checks

```bash
npm run typecheck  # tsc, strict
npm run lint       # ESLint: React hooks rules are errors, everything else is a warning
npm run build      # tsc + vite build
npm run check      # the 9 check scripts below, in sequence; exits non-zero if any fails
npm run privacy    # compares the repo (and dist/) with your real data; skips if you have none
```

`npm run check` runs `scripts/check-*.mts` with Node's type stripping:

| Script | Covers |
|---|---|
| `check-pipeline` | normalize → enrich → analytics on the demo (fixed targets) and on your real data folder (invariants only) |
| `check-history` | History aggregations, time zones, EN and PT |
| `check-subscriptions` | subscription engine and the `.ics` calendar export, synthetic scenarios |
| `check-anomalies` | alert rules |
| `check-demo` | the demo dataset contract, and the demo shifted to "today" |
| `check-sample` | the connector boundary with `fixtures/sample/`: pages, repeated rows, string amounts, refunds, voids, declines, currencies, incomplete pages, the AI files and the local merchant rules |
| `check-portfolio` | portfolio math: balance, credit, rewards, deleted or unknown values |
| `check-insights` | monthly insights, rewards since the last snapshot, and the AI summary boundary |
| `check-security` | parser and storage hardening: absurd or malformed values, oversized merchant rules, prototype names, untrusted deposit addresses |

The checks never print real values: with a real data folder present they only assert invariants (counts, sums matching, nothing dropped). Keep it that way. CI runs typecheck, lint, build, check and privacy on Node 22.23.4 and 24.22.1, without real data.

## Synthetic fixtures

`fixtures/sample/` has the exact shape of the connector responses and of the AI files (see its [README](fixtures/sample/README.md)). It is generated by `scripts/gen-sample.mjs`, which is deterministic. If you change how the connector is read (`src/lib/normalize.ts`, `src/lib/rawFiles.ts`), add the case to the generator, regenerate with `node scripts/gen-sample.mjs` and assert it in `scripts/check-sample.mts`. Never copy a value from a real response into the sample, not even "just the format".

## Privacy scan (pre-commit)

`npm run privacy` reads your real files (the data folder above) and looks for their sensitive values in everything that would be published: statement descriptors, merchant + amount pairs, ids and hashes, addresses, emails, last 4 digits, account and card names, email subjects, exact timestamps, and what belongs only to you in the local research and merchant rules. It prints only `file:line`, the level and the kind of match, never the value. With no real data, it says so and exits 0.

There are two levels:

- **GRAVE**: a full statement descriptor that identifies a place (with a number, store code, branch, tax id, or a name of 3+ words, which may be a person's), a merchant + amount pair, ids, addresses, emails, last 4 digits, email subjects, timestamps, account and card names, and notes from the local research. Always replace it with a made-up example.
- **aviso** (warning): a brand token (1 or 2 words, no number) or a public help page that happens to match your statement, local research or local merchant rules. Replace it, or, if it is a big public brand that the dictionary or the knowledge base needs for everyone, add it to [`scripts/privacy-allow.json`](scripts/privacy-allow.json) with a one-line reason. Nothing niche goes there, and the allowlist never covers GRAVE findings.

It exits with 1 when there is anything GRAVE or a warning not in the allowlist, and with 0 otherwise.

Make it a git hook, so it runs before every commit:

```bash
printf '#!/bin/sh\nnpm run --silent privacy\n' > .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

On Windows (PowerShell), Git for Windows runs hooks through its own `sh`, so there is no `chmod` step:

```powershell
Set-Content -LiteralPath .git/hooks/pre-commit -Value "#!/bin/sh`nnpm run --silent privacy`n" -Encoding Ascii
```

To see what matched, open the line: the scan never prints the value.

## Code style

- TypeScript strict, **no `any`**. React 19, Vite, Tailwind v4, Ark UI, lucide; charts in plain SVG.
- Every UI string exists in **English and Portuguese**, side by side: `tr('Spent', 'Gastei')` via `useTr()`, or `pick(locale, en, pt)`. Portuguese with correct accents. Categories are ids, labeled with `categoryLabel(id, locale)`.
- Dates: `t.date` is the local "floating" time (ISO with `Z`), `t.dateUtc` the real instant. Use `txInstant(t)` and `localToday`.
- Browser storage only through `src/lib/storage.ts` (`lighthouse:v1:` namespace, never throws).
- Text that comes from the connector or from the AI files is data, never markup: no `dangerouslySetInnerHTML`, and links pass through `safeUrl()` (`src/lib/url.ts`).
- Comments are in Portuguese in most of the code; match the file you are editing.
- Mobile first: check 320, 360, 375 and 390 px and 1366 px wide; no horizontal scroll, text ≥ 12 px, touch targets of 44 px where possible (never below 24 px), nothing hidden behind the bottom bar.
- Alerts are neutral ("check", "worth a look"); red only for what is urgent.

## Pull requests

Small and focused. Fill in the template: what and why, how to see it (route and data source), and the checklist. Screenshots only from the demo or the synthetic fixtures. By contributing you agree that your work is released under the [MIT License](LICENSE) and that you follow the [Code of Conduct](CODE_OF_CONDUCT.md). Security issues go through [SECURITY.md](SECURITY.md), not public issues.

## Releasing

Maintainers: the first public push (git identity with the noreply email, what must stay out, security settings, branch protection) and every release follow [docs/PUBLISHING.md](docs/PUBLISHING.md) for the context and [docs/RELEASING.md](docs/RELEASING.md) for the commands. Dependabot opens grouped update PRs (`.github/dependabot.yml`); they go through the same CI.

## Em português

Obrigado por ajudar! **Não precisa de conta da ether.fi**: o demo e as fixtures sintéticas cobrem todas as telas.

- **Regra principal:** nunca versione dados reais. Nada de transações, nomes da fatura, valores, endereços, ids, dígitos de cartão, emails, tokens ou prints da conta em código, comentários, testes, fixtures, docs, issues, PRs ou commits. Exemplos são sempre inventados. Os dados reais ficam só na pasta de dados, fora do git. Um resolvedor só (`scripts/data-dir.mjs`) a escolhe para o pull, o dev, os checks e a varredura, nesta ordem: `LIGHTHOUSE_DATA_DIR`; `lighthouse-data` na sua pasta de usuário (`%USERPROFILE%\lighthouse-data`, `~/lighthouse-data`), se existir; `fixtures/live/` (no `.gitignore`). Prefira a pasta de usuário, fora do projeto e **fora de pastas sincronizadas com a nuvem** (OneDrive, iCloud, Dropbox). `node scripts/data-dir.mjs` mostra qual vale; o pull recusa pasta dentro do projeto que não seja `fixtures/live/`.
- **Ambiente:** Node ≥ 22.23.4 (os checks usam `--experimental-strip-types`) e `npm ci`. `npm run dev` abre o demo; `?fixtures=sample` usa as respostas sintéticas de `fixtures/sample/`; `?fixtures` usa os seus dados do `npm run pull` (só no dev).
- **Checks:** `npm run typecheck`, `npm run lint` (hooks do React são erro, o resto é aviso), `npm run build`, `npm run check` (os 9 scripts `check-*.mts`) e `npm run privacy`. Os checks nunca imprimem valores reais.
- **Fixtures sintéticas:** geradas por `node scripts/gen-sample.mjs` (determinístico). Mudou a leitura do conector? Acrescente o caso no gerador e confira em `scripts/check-sample.mts`.
- **Varredura de privacidade como pré-commit:** `npm run privacy` compara o que seria publicado com os seus dados reais e mostra só `arquivo:linha`, o nível e o tipo. Instale o hook com os dois comandos acima. **GRAVE** (descritor completo com número, código de loja, filial, CNPJ ou nome de 3+ palavras; par estabelecimento + valor; ids, endereços, emails, últimos 4 dígitos, assuntos, timestamps, notas da pesquisa local) sempre vira exemplo fictício. **Aviso** (token de marca de 1 ou 2 palavras que coincide com a fatura, a pesquisa ou as regras locais, ou página pública de ajuda) vira fictício ou, se for marca grande e útil a qualquer pessoa, entra em `scripts/privacy-allow.json` com o motivo. Nada de nicho entra lá. Sai com 1 se houver grave ou aviso fora da allowlist.
- **Publicar:** o primeiro push público e cada release seguem o [docs/RELEASING.md](docs/RELEASING.md).
- **Estilo:** TypeScript estrito sem `any`; todo texto nas duas línguas com `tr('…', '…')` e acentuação correta; storage só pelo `src/lib/storage.ts`; links externos por `safeUrl()`; celular primeiro (320 a 390 px e 1366 px); alertas em tom neutro.
